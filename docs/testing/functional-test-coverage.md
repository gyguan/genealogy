# 功能测试覆盖基线

> Issue：#813  
> 结论口径：测试存在不等于功能已被真实验证；必须同时标注测试层级、是否 Mock、是否进入 CI。

## 2. P0 核心闭环

真实功能测试必须优先证明：

```text
登录
→ 创建宗族
→ 创建支派
→ 创建字辈方案
→ 录入人物
→ 建立关系
→ 创建并绑定来源
→ 提交审核
→ 审核通过
→ 查看人物和世系
→ 受控导出
```

最低权限反向场景：

1. 编辑人不能审核自己提交的变更；
2. 普通成员不能访问其他宗族；
3. 支派管理员不能访问兄弟支派；
4. 正式人物、关系和来源绑定不能绕过审核修改；
5. 最后一个宗族管理员不能被停用或撤权；
6. 审核驳回不得污染正式数据。

## 3. P0 数据一致性风险

| 风险 | 当前证据 | 需要的真实验证 |
|---|---|---|
| 审核快照与实时数据不一致 | 历史 PR 曾暴露字辈聚合快照问题 | 提交后修改阻断、审批按快照原子生效 |
| 通用审核 Apply 漏注册对象 | 历史 PR 曾暴露来源绑定未接入统一链路 | 每个 targetType 的真实 apply/reject 场景 |
| 权限过滤与分页顺序错误 | 规范已要求先过滤再分页 | PostgreSQL 数据集下总数和列表一致 |
| 递归支派查询越界 | 支派子树依赖递归关系 | 兄弟支派、下级支派和深层支派验证 |
| 并发重复提交或审批 | 已有部分应用层保护 | 数据库唯一约束、乐观锁和幂等验证 |
| 导入部分成功破坏一致性 | 模型测试无法证明事务行为 | 真实批次失败、重试和审核验证 |

## 4. 优先级建议

### P0

- 核心建谱全链路；
- 审核、自审阻断、快照和原子生效；
- 宗族/支派权限隔离；
- 人物关系约束；
- PostgreSQL/Flyway 初始化；
- CI 中真实执行并保留失败证据。

### P1

- 导入失败重试；
- 来源附件权限；
- 世系深层查询；
- 审计完整性；
- HTML 谱册导出；
- URL 恢复、移动端和浏览器导航。

### P2

- 大规模性能；
- 多浏览器；
- 可访问性全量审计；
- 文件异常、网络抖动和长时间任务；
- 视觉回归。

## 5. 准出原则

- `UNIT/MODEL/CONTRACT` 通过，只能说明代码级规则未回退；
- `UI_MOCK_E2E` 通过，只能说明页面在约定响应下可交互；
- P0 功能准出必须有 `DB_INTEGRATION` 或 `REAL_E2E` 证据；
- P0 失败不得通过跳过用例、删除断言或放宽权限规则处理；
- 每个失败必须关联用例编号、日志、截图/Trace 和缺陷 Issue。
