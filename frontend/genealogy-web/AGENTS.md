# Frontend AI Engineering Rules

适用于 `frontend/genealogy-web/` 及其子目录，继承仓库根 `AGENTS.md`。本文件只承载前端可执行的 P2 工程规则；复杂度阈值、拆分案例和解释见 `docs/ai/frontend-code-understanding-and-maintainability-standard.md`。

## 1. 技术基线

- React
- TypeScript
- Vite
- Ant Design 5.x
- OpenAPI 生成类型与请求能力

新增 UI 框架、状态管理库、请求库或重复基础组件前，必须说明现有能力为何不足，以及对包体积、维护成本和迁移路径的影响。

## 2. 组件与设计体系

1. 基础 UI 优先使用 Ant Design，不建立第二套 Button、Table、Form、Modal 等基础体系。
2. `shared/ui` 只做基于 Ant Design 的薄封装。
3. 自定义组件只用于图谱、关系连线、树谱画布等基础组件无法覆盖的业务可视化。
4. 页面复用统一布局、间距、表格、表单和反馈模式，不为单页另起视觉规范。
5. 页面容器负责用例编排；展示组件负责渲染；Feature Hook 负责可复用状态与副作用；Service/API 层负责请求。
6. UI 组件不直接调用业务 API，业务页面不承担通用基础组件职责。
7. 组件、Hook 和 Service 名称必须表达业务意图，避免新增模糊的 `Common`、`Manager`、`Data`、`Helper`、`Content`。
8. 普通用户页面展示业务名称和业务文案，不要求用户识别技术 ID、字段名或原始枚举。

视觉与页面模式的权威规范：

- `docs/10-frontend-design-guidelines.md`
- `docs/21-frontend-page-pattern-spec.md`
- `docs/22-multi-tab-page-spec.md`

## 3. 页面状态与交互

每个异步页面必须处理：加载、空、错误、无权限、提交中、重复提交保护和成功/失败反馈。

- 可分享、刷新或返回恢复的筛选、分页、排序、Tab 和范围优先同步到 URL。
- 高风险操作明确对象、影响和必要原因，使用确认交互并展示后端真实拒绝原因。
- 不使用隐藏按钮代替后端安全校验。
- 互斥流程使用联合类型、枚举或显式状态对象，不用多个松散布尔值表达。
- 不通过 DOM 查询、文本内容或元素存在性判断业务状态。

## 4. API、类型与模型边界

1. API 变更先更新 `docs/api/openapi.json`，再执行 `npm run api:generate` 和 `npm run api:check`。
2. 优先使用生成的请求与类型，不手工复制后端 DTO。
3. 不通过 `any`、重复接口定义、宽松断言或兜底字段掩盖契约不一致。
4. 旧字段兼容必须与后端窗口一致，并标明移除条件。
5. 页面不得自行推断审核结果、权限范围、正式状态或隐私结果。
6. 错误处理区分业务错误、无权限、网络失败和系统异常。
7. API DTO、页面 ViewModel、FormValues 和 Submit Command 边界清晰，转换显式且可测试。
8. 页面不散落拼接 API 路径；请求按 Feature 收敛到 `api/` 或 `services/`。
9. 搜索请求考虑防抖、最小触发条件和过期请求取消。
10. 新增展示字段前确认 OpenAPI 中存在，不在前端补造真实业务数据。

## 5. 权限、隐私与业务字典

- 前端只负责降低误操作和改善体验，后端负责最终授权。
- 按对象使用后端返回的 `allowedActions`，不把通用权限套用到所有行。
- 不根据角色名自行推断宗族、支派或对象级权限。
- 无权数据不先加载再隐藏。
- 在世人员、联系方式、附件和来源材料按后端脱敏结果展示，不恢复完整值。
- 导出、下载和附件预览保留真实权限与审计语义。
- 权限、状态、错误码和业务字典映射集中维护，不在页面内重复定义。

## 6. 状态归属

状态必须有唯一权威来源：

| 状态类型 | 归属 |
|---|---|
| 接口数据、分页、请求状态 | 请求层或 Feature Hook |
| 可分享筛选、分页、Tab、范围 | URL |
| Drawer、Modal、选中对象 | 页面局部 state |
| 表单字段 | Ant Design Form |
| 可由其他值计算的内容 | 派生状态，不重复保存 |
| 跨页面稳定上下文 | 已有 `shared/context` |

必须遵守：

- 不为单一页面引入全局状态。
- 不同时维护 Form 值和镜像 `useState`。
- 请求、展示、转换和副作用职责分离。
- 公共组件必须有明确复用场景，不为一次使用提前抽象。
- Props 透传超过两级时，评估组件边界、组合模式或已有 Context。
- 不静默吞掉异常，不在控制台保留敏感数据和调试输出。

## 7. Hook 与副作用

1. `useEffect` 只用于同步 React 与外部系统，不替代普通计算和事件处理。
2. 一个 Effect 只负责一种外部副作用。
3. 依赖数组完整，不通过禁用规则掩盖依赖问题。
4. 订阅、定时器和事件监听提供 cleanup。
5. 请求竞争通过取消、请求序号或丢弃过期结果处理。
6. 不在 Effect 中循环同步多个可派生 state。
7. 自定义 Hook 以 `use` 开头并表达业务意图。
8. Hook 不混合多个无关状态域；多个独立副作用应评估拆分。
9. 消息提示由明确用户动作或请求结果触发，避免重复渲染反复弹出。

## 8. Props、事件与展示组件

- Props 使用明确类型，不用无语义的 `data`、`info` 承载复杂对象。
- 数据字段使用名词，事件使用业务动作，例如 `onReviewApprove`。
- 多个相关事件可归并为类型化 `actions` 对象。
- Props 过多时评估 ViewModel、Action 对象或组件拆分。
- 列表 `key` 使用稳定业务标识，不使用数组下标。
- 展示组件原则上无副作用，不直接读取路由、全局对象或业务 API。

## 9. 表格、表单与弹窗

### 表格

- 列定义按 Feature 收敛，避免页面内超长内联数组。
- 行操作基于每行 `allowedActions`。
- 排序、分页和筛选与后端契约一致。
- 大数据量使用后端分页，不在前端截取无界结果模拟分页。
- render 中不发请求、不执行昂贵排序、分组和转换。
- 使用稳定 `rowKey`。

### 表单

- Ant Design Form 是单一表单状态源。
- 校验规则集中、可复用，并与后端约束一致。
- DTO → FormValues → Command 转换显式分离。
- 提交中防止重复提交；失败后保留用户输入并展示可操作错误。
- 大表单按业务段落拆分，不按行数机械拆分。

### Drawer / Modal

- 打开对象、模式和动作显式。
- 关闭时清理短生命周期状态。
- 不在多个弹窗间共享含义模糊的 `currentRecord`。
- 高风险操作明确对象、影响和原因。

## 10. 性能与复杂 Feature

- 列表采用后端分页、稳定排序和稳定 key。
- 搜索处理防抖和过期请求。
- 不在 render 中发请求或做昂贵转换。
- 优先通过职责和状态边界减少重渲染，不盲目增加 `memo`、`useMemo`、`useCallback`。
- 图谱和大列表明确深度、节点、边、数量上限与降级方式。
- 不一次性拉取无边界全宗族数据。
- 大文件上传、导入和长任务以后端任务状态为准，不在浏览器无界解析。
- 超过经验文档建议阈值时，在 PR 中说明职责边界和风险控制。

复杂 Feature 的目录、调用链和 README 条件见 `src/features/README.md`。

## 11. 测试要求

优先覆盖：

- 加载、空、错误、无权限和提交状态；
- URL 状态恢复；
- 权限动作和高风险操作；
- 表单失败后的输入保留；
- 过期请求和重复提交；
- API DTO 到 ViewModel/FormValues/Command 的转换；
- 图谱、列表和导入的性能边界；
- 关键真实浏览器链路。

测试名称描述业务条件和期望结果。禁止通过删除断言、快照或跳过用例让构建通过。

## 12. 验证与完成检查

默认执行：

```bash
cd frontend/genealogy-web
npm run typecheck
npm run build
npm run api:check
```

涉及 OpenAPI 时增加：

```bash
npm run api:generate
```

页面、样式或交互变化根据范围执行 Playwright、视觉发布、多浏览器和 DOM/CSS 治理门禁。

完成前确认：

- 使用统一设计体系，没有重复基础组件；
- 页面完整状态和高风险交互已覆盖；
- API、类型、ViewModel 和表单边界清晰；
- 权限和隐私展示未替代后端判断；
- 列表、搜索、图谱和导入具备明确边界；
- 复杂度偏离、未执行验证和已知风险已写入 PR。
